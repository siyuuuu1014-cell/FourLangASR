### 新增：真机仪器化测试基础设施

之前项目只有 JVM 单测（`app/src/test`），原生引擎路径（sherpa-onnx /
Vosk / TFLite / 3D-Speaker）完全没有自动化覆盖。本次补上：

- `app/src/androidTest/java/com/example/fourlangasr/OnDevicePipelineTest.kt`
  —— 9 个用例，用真实 WAV 驱动真实引擎：
  VAD 断句、ZH/EN/RU/UZ 四语种 ASR、LID 四语种路由、
  Speaker 同人/异人、AsrManager 语种切换与复用。
- `app/src/androidTest/assets/audio/` —— 6 个 16 kHz mono 16-bit 样本，
  取自 `experiments/speaker/speaker_data`（Mozilla Common Voice 派生）。
- `app/build.gradle`：加 `testInstrumentationRunner` 与
  `androidx.test.{ext:junit,runner,rules}`。

### 结果

- JVM 单测 25/25 通过（CodeSwitch 9、ModelModel 4、M2mTokenizer 6、TTS 6）。
- `assembleDebug` 通过；真机（PLW110 / arm64-v8a / Android 16）安装启动无崩溃。
- 仪器化 9/9 通过。实测关键数据：
  - ASR 加载 1.2~1.6 s；RTF 0.04~0.06（ZH/EN），RU 0.23。
  - LID 四语种全对，conf4 0.97~1.00。
  - Speaker 同人 0.702（阈值 0.45）、异人 0.243 → 正确区分。
  - AsrManager ZH→EN→ZH 切换正常，重载 1.2 s。
- UI 交互（模式切换 AUTO/MANUAL、语言下拉、自动朗读、语速、
  专项模型页）经 adb 点击验证均正常。

### 踩坑（重要）

1. **测试样本能量决定成败**。首轮用的
   `zh/speaker_1/enroll/01.wav` RMS 只有 0.0058（近乎静音），
   导致 VAD 只切出 0.45 s、ZH 只识别出「九」、Speaker 同人分
   只有 0.392（低于阈值 → 误建档案）。换成 RMS≈0.13 的样本后
   全部恢复正常。**以后选测试音频必须先看 RMS/能量占比**。
2. **`connectedDebugAndroidTest` 会先卸载主 APK**，
   586 MB 的 APK 重装时抛 `Failure [-99]`，UTP 流程直接失败，
   且会留下「只剩 .test 包」的脏状态。绕过办法：
   手动 `adb install -r -t` 主 APK → 再装 test APK →
   用 `adb shell am instrument -w -r -e class <类>#<方法> ...` 运行。
3. 单进程内连续跑全部用例时，中途出现一次 `Process crashed`
   （在 Speaker 用例）。改成**每个用例单独 `am instrument`**
   后稳定通过。判断与近静音输入 + 原生内存累积有关。
4. `JAVA_HOME` 必须是 Windows 风格路径
   （`C:\Program Files\Eclipse Adoptium\jdk-17.0.20.101-hotspot`），
   Git Bash 的 `/c/...` 形式会被 gradlew 判为无效目录。
